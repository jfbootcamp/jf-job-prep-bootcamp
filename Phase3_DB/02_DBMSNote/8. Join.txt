0. 조인(Join)이 필요한 이유
    1) 만약 모든 데이터를 하나의 테이블에 저장한다면?
        - 데이터 중복
        - 갱신 이상
        - 삽입 이상
        - 삭제 이상

    2) 데이터베이스 설계할 때 정규화(Normalization)라는 과정을 거침        
        - 데이터의 중복 최소화 
        - 데이터의 일관성을 해치는 이상 현상들을 방지 
        - 데이터를 논리적인 단위로 분리하는 과정 

    3) 잘 관리하기 위해서 흩어놓은 데이터에서 의미 있는 정보을 얻으려면,
       이 흩어진 조각들을 다시 합쳐야만 함.
       - 예) 이순신 고객이 어떤 상품을 주문했는지 출력하시오.
                   ---       ---   ---         
       - 분리된 테이블들을 다시 연결해야 함
        --> 이때 사용하는 기술이 바로 조인(Join)임.              

1. 조인(Join) 의미
    1) 서로 다른 테이블을 공통 컬럼을 기준으로 합치는(겹합하는) 테이블 단위 연산
    2) 조인의 결과 테이블은 이전 테이블의 컬럼 수의 합과 같음 
    3) 조인시 서로 다른 테이블에 같은 컬럼명이 존재하면 구분을 위해 
       테이블명.컬럼명으로 사용해서 표시함 

2. 내부 조인 (Inner Join)
    1) 두 테이블을 연결할 때, 양쪽 테이블에 모두 공통으로 존재하는 데이터만을 
       결과로 보여줌.
    2) 기준이 되는 컬럼의 값이 서로 일치하는 행들만 짝을 지어주는 것임.
        - 등가 조인(= Equi JOIN)
    3) 문법 
        SELECT 컬럼1, 컬럼2
        FROM 테이블A (INNER) JOIN 테이블B
        ON 테이블A.연결컬럼 = 테이블B.연결컬럼;

        (오라클)
        SELECT 컬럼1, 컬럼2
        FROM 테이블A, 테이블B
        WHERE 테이블A.연결컬럼 = 테이블B.연결컬럼;
    4) 양쪽 테이블에 모두 존재하는 데이터만 결과로 보여줌 
    5) 교집합 (Intersection)만 반환
        - 양쪽 모두 매칭되는 행만 결과에 포함
    6) 가장 일반적인 조인 방식 
    7) 가장 많이 사용되는 Join    
    8) Null은 매칭 불가 
        - NULL = NULL은 false   
        - NULL 행은 항상 제외  
    9) JOIN = INNER JOIN
        - INNER 키워드 생략 가능       
        - JOIN만 써도 동일  
    10) 별칭 사용  
        - 테이블명이 길면 별칭으로 간결하게 사용  
    11) 가장 많이 사용되는 JOIN                  

3. LEFT JOIN             
    1) 왼쪽 테이블의 모든 행을 유지하고, 오른쪽에 매칭이 없으면 NULL로 채움 
    2) 왼쪽 테이블 전체 + 오른쪽 매칭 행 
       매칭이 없으면 오른쪽 = NULL 
    3) 두번째로 많이 사용되는 JOIN        
    4) 기본 문법
        FROM A LEFT JOIN B ON A.id = B.id 

4. RIGHT JOIN 
    1) 오른쪽 테이블 전체 + 왼쪽 매칭 행 
    2) 매칭 없으면 = NULL 
    3) LEFT JOIN으로 대체 가능!
    4) 기본 문법 
        FROM A RIGHT JOIN B ON A.id = B.id     

5. CROSS JOIN (카테시안 곱)
    1) A * B = 모든 조합 
        - A=3행, B=4행 --> 결과 = 12행 
    2) JOIN 조건 없음
    3) 테스트 데이터 생성에 활용                 

6. SELF JOIN
    1) 자기 참조
    2) 같은 테이블을 두번 JOIN 
    3) 계층 구조 (상사-부하) 조회에 활용 
    4) 반드시 별칭(alias) 사용 
        - 같은 테이블이지만 "역할"이 다르기 때문.
