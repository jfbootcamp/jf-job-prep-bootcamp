1. 데이터 저장의 역사 (Part1)
    1) 1950s
        - 천공카드 (Punch Card)
            - 카드에 구멍을 뚫어 데이터 표현 
            - 미국 인구조사(1890)에서 최초 대규모 사용 
    2) 1950s 후반 ~ 1960s
        - 자기 테이프 (Magnetic Tape)
            - 대량 데이터 저장 가능 (수 MB)
            - 순차 접근만 가능 
                - 오늘날에도 대용량 백업 용도로 사용 중!
    3) 1960s
        - 자기 디스크 (Magnetic Disk)
            - 랜덤 엑세스 가능 (게임 체인저)                
            - 파일 시스템의 기반이 됨 
            - 현대 HDD/SSD의 조상 

    4) 위 1)~3)시기의 핵심 문제
        - 각 프로그램이 자기만의 방식으로 데이터 파일 관리 (데이터 형식이 다름)              
        - 같은 데이터가 여러 파일에 중복 저장 --> 수정 시 모든 파일을 일일이 변경해야 함 
        - "데이터를 체계적으로 관리하는 새로운 방법이 필요하다" ---> 파일 시스템의 등장  

    5) 파일 시스템의 등장 (1960 ~ 1970s)
        - 자기 디스크의 등장으로 파일 시스템이 보편화됨
        - 기업 데이터가 늘어나면서 심각한 문제가 드러남 
        - 파일 시스템의 4대 문제점 
            - 데이터 중복
            - 일관성 문제 
            - 동시 접근 (충돌)    
            - 보안 취약 
        - 근본 원인
            - 프로그램과 데이터가 강하게 결합 
            - 프로그램이 바뀌면 형식도 바꿔야 함      

2. 데이터 저장의 역사 (Part2)
    1) 최초의 데이터베이스 탄생 (1960 ~ 1970s)
        - 파일 시스템의 한계를 극복하기 위해 데이터를 중앙에서 통합 관리하는 
          "데이터베이스" 개념이 등장함 
    2) IDS (Integrated Data Store) (1963년)
        - 찰스 바크먼 (Charles Bachman)
            - 세계 최초의 DBMS 개념 
            - 네트워크 모델의 원형 
            - 1973년 튜링상 수상 (DB 분야 최초)
    3) IMS (Information Management System) (1966년)
        - IBM 
        - 아폴로 달 착륙 프로젝트의 부품 관리에 사용 
        - 계층형 데이터베이스
        - 트리(나무) 구조로 데이터 관리
        - 부모-자삭 관계로 데이터 연결              
    4) CODASYL (Conference/Committee on Data Systems Languages) (1969년)
        - CODASYL 위원회 (산업 표준화)
        - 네트워크 모델 
        - 그래프 구조 (다대다 관계 지원)
        - 계층형보다 유연한 관계 표현 
    5) 초기 DBMS의 한계
        - 탐색 경로를 프로그래머가 직접 지정해야 함 
        - 구조 변경 시 프로그램 전체를 수정해야 함 
        - 물리적 저장 구조에 프로그램이 종속 
    6) 데이터의 물리적 저장 방식과 논리적 구조를 분리할 수는 없을까? 
        - 관계형 모델의 등장!   

3. 데이터 저장의 역사 (Part3)
    1) RDBMS의 탄생 (1970s~1980s)
        - 관계형 혁명 
    2) 에드거 F. 코드 (IBM 연구원)    
        - 1970년 역사적 논문
            - 관계형 모델 제안  
        - 핵심 아이디어
            - 데이터를 단순한 "테이블(표)"로 표현하자!
            - 물리적 저장과 논리적 구조를 완전히 분리 
            - 수학적 기반
                - 집합론(Set Theory)
    3) RDBMS 타임라인
        - 1973
            - IBM System R 프로젝트 시작 --> SQL 탄생
        - 1977
            - 래리 엘리슨 (Larry Ellison) Oracle 설립
        - 1979
            - Oracle V2 출시 
            - 최초 상용 RDBMS 
        - 1981
            - IBM SQL/DS 출시 --> DB2로 발전                            

4. 데이터 저장의 역사 (Part4)            
    1) RDBMS 시대의 개막 (1980s ~ 현재)
        - SQL이 표준화되고, 다양한 RDBMS 제품들이 등장
        - 오늘날의 데이터베이스 생태계가 형성됨 

    2) SQL 표준화
        - 1986: ANSI SQL 표준 제정 (SQL-86)
        - 1992: SQL-92 (가장 널리 참조되는 표준)
        - 1999~현재: SQL:1999, 2003, 2011, 2016, 2023 계속 발전 중 
        - 어떤 RDBMS를 쓰든 SQL 문법은 거의 동일!

    3) 왜 RDBMS가 승리했나?
        - 직관적: 테이블(표)은 누구나 이해할 수 있는 구조 
        - SQL : 영어처럼 읽히는 배우기 쉬운 표준 언어
        - 트랜잭션 : 데이터 안정성을 수학적으로 보장 
        - 유연성 : 데이터 구조를 쉽게 변경 가능 (Alter table)  

    4) 주요 RDBMS 제품 타임라인                   
        - Oracle(1979 ~ )
            - 최초의 상용 RDBMS
            - 대기업/금융권 표준
            - 엔터프라이즈 시장 1위 
        - DB2 (1983~ )
            - IBM의 관계형 DB 
            - System R의 직계 후손 
            - 메인프레임 시장 강자 
        - SQL Server (1989~)
            - MiscroSoft의 RDBMS
            - Windows 생태계 통합
            - .NET 개발자에게 인기 
        - MySQL (1995~)
            - 오픈소스 혁명의 시작 
            - 가볍고 빠름, 웹 서비스 표준 
        - PostgreSQL (1996~)
            - UC Berkeley에서 시작
            - 기능 풍부, SQL 표준 준수 
            - 최근 가장 빠르게 성장 중
