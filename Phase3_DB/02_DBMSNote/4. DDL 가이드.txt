1. 데이터베이스(Database)
    1) 구조화된 데이터의 집합으로, 효율적으로 저장, 관리, 검색할 수 있도록 
       조직된 정보의 모음임.

    2) 파일 시스템   vs     데이터베이스 
      ----------------------------------
       데이터 중복           데이터 무결성 
       일관성 유지 어려움     보안 및 백업 
       동시 접근 문제        동시성 제어       

2. DBMS (Database Management System)
    1) 데이터베이스를 관리하기 위한 소프트웨어 시스템임 
    2) 유형 
        - RDBMS
            - 관계형, 테이블 기반, SQL 사용 
        - NoSQL 
            - 비관계형, 유연한 스키마 
            - MongoDB, Redis  
                    
3. RDBMS 핵심 개념
    1) 테이블 (Table) = 릴레이션 (Relation)                    
        - 행 (Row) = 튜플 (Tuple) = 레코드 (Recode)
        - 열 (Column) = 속성 (Attribute) = 필드 (Field)
        - 기본키 (Primary Key) = 행을 고유하게 식별 
        - 외래키 (Foreign Key) = 다른 테이블 참조 
        - 인덱스 (Index) = 검색 속독 향상 

4. SQL 명령어 분류
    1) 용도에 따라 4가지로 분류 (비유: 건축) 
        - DDL (Data Definition Language) : 설계도 & 건물 (건물 짓기/허물기)
        - DML (Data Manipulation Language) : 입주 & 생활 (가구 배치/이동)
        - DCL (Data Control Language) : 보안 관리 (출입증 발급)
        - TCL (Transaction Control Language) : 안전 장치 (공사 확정/취소) 

5. DDL 
    1) 구조 정의 
    2) 데이터베이스/테이블의 구조를 만들고 변경하고 삭제 
    3) 명령어
        - CREATE : DB/테이블/인덱스 생성
        - Alter : 테이블 구조 변경 (컬럼 추가/수정/삭제)
        - DROP : DB/테이블 완전 삭제 (구조+데이터)
        - TRUNCATE : 테이블 데이터만 전체 삭제 (구조유지)
    4) 핵심 특징
        - DDL은 Auto Commit! 
            - 실행 즉시 확정되어 ROLLBACK 불가함!     
    5) 학습순서 
        - ① CREATE DATABASE (DB 생성)
          ② 데이터 타입 정하기 BIGINT, VARCHAR...
          ③ CREATE TABLE (테이블 생성)
          ④ 제약조건 정하기 PK, FK, NOT NULL 
          ⑤ Alter TABLE 구조 변경
          ⑥ DROP/TRUNCATE 삭제  

6. DML
    1) 데이터를 조작 (CRUD)
    2) 명령어
        - SELECT : 조회
        - INSERT : 삽입
        - UPDATE : 수정
        - DELETE : 삭제     
    3) DML은 TCL로 ROLLBACK 가능함, DDL은 Auto Commit이라 불가함.        

7. DCL
    1) 권한을 관리
    2) 명령어
        - GRANT : 권한 부여
        - REVOKE : 권한 회수 

8. TCL
    1) 트랜잭션을 제어
    2) 명령어
        - COMMIT : 변경 확정
        - ROLLBACK : 변경 취소 
        - SAVEPOINT : 중간 저장점

10. 테이블 생성 
    1) 기본 문법 구조 
        - CREATE TABLE 테이블명 (
            컬럼명1     데이터타입      [제약조건],
            컬럼명2     데이터타입      [제약조건],
            ...
            [테이블 레벨 제약조건]
        ) ENGINE=InnoDB
          default charset=utf8mb4
          comment='도서관 회원';

11. 제약조건(Constraints)
    1) 데이터를 지키는 규칙 
    2) 입력 양식의 유효성 검사!
    3) 종류
        - primary key (기본값)
            - 각 행을 고유하게 식별하는 컬럼
            - not null + unique 자동 적용
            - 테이블당 1개만 가능 
            - 자동으로 인덱스 생성
            - 모든 테이블에 PK는 필수임 

        - not null (필수값)
            - NULL(빈값)을 허용하지 않음
            - 반드시 값이 있어야 INSERT 가능  

        - unique (고유값)     
            - 중복 값을 허용하지 않음 
            - NULL은 여러개 가능

        - FOREIGN KEY (외래키)
            - 다른 테이블의 PK를 참조하는 컬럼 
            - 참조 무결성 보장 (없는 값 참조 불가)
                - 비유 : 주문의 고객ID --> 고객 테이블에 실제 존재해야함 
            - InnoDB만 지원

        - COMMENT '설명'
            - 컬럼 설명 (선택)  

        - DEFAULT (기본값)
            - 값을 안 넣으면 자동으로 들어갈 값 

        - CHECK (값 범위 제한)
            - 입력 값의 조건을 지정             

            
12. FOREIGN KEY 심화 (부모 삭제 시 자식은 어떻게 될까?)                       
    1) 비유 
        - 학과가 폐지되면 소속 학생은?
            - CASCADE (학생도 삭제)
            - SET NULL (무소속 처리)
            - RESTRICT (학생 있으면 폐지 불가)

    2) 문법
        CONSTRAINTS fk_이름 FOREIGN KEY (자식 컬럼) REFERENCES 부모_테이블(부모_PK) 
                                                            ON DELETE [옵션] ON UPDATE [옵션]            
        -- 옵션 : CASCADE | SET NULL | RESTRICT 

    3) CASCADE (연쇄 삭제/수정)
        - 부모 삭제 --> 자식도 함께 삭제
          부모 PK 수정 --> 자식 FK도 함께 수정 
        - 예)
            ON DELETE CASCADE
            주문 삭제 -->  주문 상세도 삭제    
            게시글 삭제 --> 게시글 상세,댓글 삭제   

    4) SET NULL (NULL로 변경) 
        - 부모 삭제 --> 자식의 FK를 NULL로 변경 (자식 데이터는 유지)
        - 예)
            ON DELETE SET NULL 
            카테고리 삭제 --> 상품의 카테고리=NULL 
            직원-부서
            (부모 없어도 자식은 유지해야 하는 경우)    

    5) RESTRICT (삭제 거부, 가장 안전한 옵션-기본값)
        - 자식이 참조 중이면 --> 부모 삭제 불가! (에러 발생)
        - 예)
            ON DELETE RESTRICT
            주문이 있는 회원 --> 회원 삭제 거부!   
            회원-주문, 도서-대출
            (자식이 있으면 부모를 함부로 삭제하면 안되는 경우)                

13. ALTER TABLE 
    1) 이미 만든 테이블 구조 변경하기 
    2) 비유
        - 이미 지은 건물에 방 추가 (ADD)
        - 방 크기 변경 (MODIFY)
        - 방 이름 변경 (CHANGE)
        - 방 철거 (DROP)
        --> 건물은 그대로!
    3) 명령어
        - ADD COLUMN (컬럼 추가)     
        - MODIFY COLUMN (타입/제약조건 변경)   
        - CHANGE COLUMN (컬럼 이름 변경, 타입 변경 가능) 
        - DROP COLUMN (컬럼 삭제)
            - 데이터도 사라짐! 복구 불가! 
            - PK 컬럼, FK가 참조하는 컬럼은 삭제 불가!
                - 실무에서는 삭제 대신 is_deleted 컬럼 추가 (소프트 삭제)
