1. 쇼핑몰 DB 설계 
    1) 논리적 모델링 --> 물리적 모델링 --> DDL 구현 
    2) 온라인 쇼핑몰 테이블 
        - 부모 테이블 먼저
            - members (회원)
            - categories (카테고리)
            - coupons (쿠폰)
        - 자식 테이블 (FK 포함)
            - addresses (배송지)
            - products (상품)
            - orders (주문)
        - N : M 테이블 (FK 2개 이상)
            - N : M 테이블로 못 만듦
                - 회원 1명이 상품 여러 개를 주문하고, 상품 1개도 여러 회원이 주문함 
                - 이런 N : M 관계는 두 테이블만으로는 표현이 안됨 
                - 해결책 : 중간 테이블을 만듦
                    - 둘 사이에 끼어드는 테이블을 하나 만듦
                    - 이 테이블이 양쪽 PK를 FK로 갖고, N:M -> 1:N + N:1로 풀어줌 
            - 테이블 소개 

                테이블          연결하는 관계           비유설명            핵심 추가 컬럼
               ----------------------------------------------------------------------
               order_items      주문<-->상품      주문 1건에 여러 상품,      quantity,
                                                 같은 상품이 여러 주문에    unit_price
               cart_items       회원<-->상품      장바구니에 여러 상품 담기   quantity,                                   
                                                                         added_at  
                reviews         회원<-->상품      내가 산 상품에 리뷰 남기기   rating, content 
                coupon_issues   쿠폰<-->회원      쿠폰을 누가 받았고, 어디에   is_used, used_at,
                                (+주문)           썼는지                    order_id

2. EER Diagram
    1) Enhanced Entity-Relationship (확장 개체-관계) 다이어그램 
    2) 테이블, 컬럼, PK, FK, 관계(1:N, N:M)를 그림으로 그리는 도구 
    3) 그림을 그리면 Workbench가 자동으로 DDL을 생성해 줌 (Forward Engineering)     

3. 셀프 참조 (Self-Referencing FK) 설정
    1) 같은 테이블 안에서 FK가 자기 자신의 PK를 참조 
    2) 예
        - 쇼핑몰의 categories
            - parent_category_id --> category_id (자기 자신 참조)
            - 대분류 --> 중분류 --> 소분류 계층 구조 표현 
            - Workbench 연결 방법
                - 1 : N Non-Indentifying 도구 선택
                - categories 테이블 클릭 (자식=자기 자신)
                - categories 테이블 다시 클릭 (부모=자기 자신)       

4. 논리적 모델링 -- 관계 설정 (FK 연결)
    1) 테이블 사이에 FK(외래키) 관계를 그려 넣는 단계 
    2) Workbench  관계 도구 (EER 툴바)
        - 1 : n Indentifying (식별관계) 
            - PK가 FK에 포함됨 (복합 PK의 일부)
                - FK가 자식 테이블의 PK의 일부가 됨 
            - 실선 + 실선으로 표시
            - 자식이 부모 없이 존재할 수 없음     

        - 1 : N Non-Indentifying (비식별관계)
            - FK가 일반 컬럼으로 추가됨  
            - 가장 많이 사용 
            - 점선으로 표시 
            - 자식이 독립적으로 존재 가능 

        - 어떤 걸 선택하나요?
            - 자식 테이블이 자체 AUTO_INCREMENT PK를 갖고 있으면  Non-Indentifying (대부분의 경우)   
            - FK가 PK의 일부인 복합키 구조이면 Indentifying 

    3) 관계 연결 방법 
        - STEP1
            - 툴바에서  1 : N Non-Indentifying 도구를 클릭 (커서가 십자모양으로 변경)
        - STEP2
            - 자식 테이블을 먼저 클릭 (FK를 받을 쪽)
        - STEP3
            - 부모 테이블을 클릭 (PK를 가진 쪽)   

    4) 쇼핑몰 전체 관계 연결 체크 리스트 
        - 요구사항에서 도출하기 (어떤 관계가 필요한지 직접 판단)
        - Group A:    1 : N 직접 관계 (한쪽이 다른 쪽을 소유/소속하는 관계)
            - 관계1 
                - address --> members  :  회원 1명 --> 배송지 여러 개
            - 관계2
                - products --> categories : 카테고리 1개 --> 상품 여러 개                              
            - 관계3
                - categories --> categories :  셀프 참조 (대->중->소)
            - 관계4
                - orders --> members : 회원은 여러 번 주문 할수 있음 - 반복구매, 주문 이력 관리
            - 관계5
                - orders --> addresses :  주문 시 배송 받을 주소를 지정함 - 매번 다른 배송지 선택 가능                      
        - Group B:    N : M 해소 관계 (양쪽 모두 여러개인 행위/이벤트 관계)
            - 관계 6-7
                - 요구사항 : 회원이 상품을 주문한다.
                    - 1명이 여러 상품 주문 
                    - 1상품이 여러 회원에게 주문됨   
                    --> N:M 
                    - 관계 자체의 속성 : 수량(quantity), 주문 시점 가격(unit_price)
                - 관계6
                    - order_items --> orders (주문-상품)
                - 관계 7
                    - order_items --> products (주문-상품)        
            - 관계 8-9
                - 요구사항 : 회원이 상품을 장바구니에 담는다.
                    - 1명이 여러 상품 담기
                    - 1상품이 여러 회원 장바구니에 담기 
                    --> N:M
                    - 관계 자체의 속성 : 수량(quantity), 담은 시간(created_at) 
                - 관계 8
                    - cart_items --> members | cart_items.member_id --> members.member_id (회원-장바구니)
                - 관계 9
                    - cart_items --> products | cart_items.product_id --> products.product_id (회원-장바구니)        

            - 관계 10-11
                - 요구사항 : 회원이 구매한 상품에 리뷰와 별점을 남긴다.
                    - 1명이 여러 상품에 리뷰 / 1상품에 여러 회원 리뷰 --> N:M 
                    - 관계 자체의 속성 : 별점(rating), 리뷰 내용(content)
                - 관계 10
                    - reviews --> members | reviews.member_id --> members.member_id (회원-리뷰)                                                     
                - 관계 11
                    - reviews --> products | reviews.product_id --> products.product_id (회원-리뷰)                    

            - 관계 12-14 
                - 요구사항 : 쿠폰을 회원에게 발급하고, 주문 시 사용한다.   
                    - 1쿠폰이 여러 회원에게 / 1회원이 여러 쿠폰 / --> N : M + 사용된 주문(order_id) 추적
                    - 관계 자체의 속성 :  사용여부(is_used), 사용시간(used_at) / FK 3개 (쿠폰,회원,주문)
                - 관계 12
                    - coupon_issues --> coupons | coupon_issues.coupon_id --> coupons.coupon_id (쿠폰-발급)
                - 관계 13
                    - coupon_issues --> members | coupon_issues.member_id --> members.member_id (쿠폰-발급)                                                       
                - 관계 14
                    - coupon_issues --> orders | coupon_issues.order_id --> orders.order_id (쿠폰-발급)                    

    5) ON DELETE / ON UPDATE 설정
        - 부모 테이블의 행이 삭제/수정될 때, 자식 테이블의 FK 데이터를 어떻게 처리할지 결정하는 옵션
        - RESTRICT (기본값)
            - 자식 데이터가 있으면 삭제/수정 거부!
            - 예) 주문이 존재하는 회원은 삭제 불가 
            - 가장 안전 
            - 대부분 이것 사용 
        - CASCADE 
            - 부모가 삭제되면 자식도 같이 삭제!
            - 부모 PK 수정되면 자식 FK도 같이 수정!
            - 예) 회원 탈퇴 --> 배송지도 자동 삭제 
            - 위험할 수 있음 
            - 연쇄 삭제 주의 
        - SET NULL 
            - 부모가 삭제되면 자식 FK를 NULL로!
            - 예) 카테고리 삭제 --> 상품의 category_id = NULL (미분류 처리)
            - FK 컬럼이 NOT NULL이면 사용 불가 
        - NO ACTION
            - MySQL에서는 RESTRICT와 동일
            - 실무에서는 RESTRICT와 같다고 생각하면 됨
