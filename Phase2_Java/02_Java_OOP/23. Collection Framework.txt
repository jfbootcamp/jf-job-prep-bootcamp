0. 컬렉션 프레임워크 
    1) 일상에서 이미 쓰고 있는 컬렉션
        - 카카오톡 채팅방
           - 메시지가 순서대로 쌓임
           - 새 메시지는 맨 아래에 추가
           - 스크롤하면 위에서부터 읽음
           --> List 임 (순서가 있고, 중복 허용)  
        - 수강생 출석체크 
           - 같은 이름은 한 번만 체크 
           - 순서는 상관없음
           - 누가 왔는지만 중요 
           --> Set 임 (순서 없고, 중복 불허)
        - 연락처 (전화번호부)
           - 이름으로 번호를 찾음
           - 이름이 Key, 번호가 Value
           - 같은 이름(Key) 중복 불가 
           --> Map 임 (Key로 Value를 찾는 구조)                                                                                                                                          


1. 배열의 한계
    1) 크기 변경 불가 (--> 처음에 몇 개 들어올지 모르면?)
    2) 중간 삽입/삭제 (--> 직접 밀고 당겨야 함)
    3) 현재 몇 개 들어있는지 직접 관리해야함
    4) 배열을 쓰는 경우
        - 크기가 절대 변하지 않을 때 (예: 요일 7개, 월 12개)

2. ArrayList
    1) 크기 자동 조절 --> 데이터 몇 개든 OK 
    2) add/remove() --> 추가/삭제 메서드 제공
    3) size() --> 현재 개수를 자동 관리     
    4) ArrayList 쓰는 경우
        - 데이터가 동적으로 추가/삭제 될때 (예: 직원 목록, 주문 목록, 로또 번호)

3. 배열 vs ArrayList 메서드 비교

        기능                  배열(Array)             ArrayList
      ------------------------------------------------------------------
        생성                new String[3]            new ArrayList<>()
        추가                arr[0] = "값"            list.add("값")
        조회                arr[0]                   list.get(0)
        크기                arr.length               list.size()
        삭제                (직접 구현해야 함)         list.remove(0)
        포함여부             (직접 반복문 실행해야함)    list.contain("값")  

4. ArrayList vs HashSet - 중복 처리 방식 비교 

        비교 항목            ArrayList + contains()                    HashSet
      ------------------------------------------------------------------------------------------------------                                              
        중복 처리            수동 체크 필요 (contains --> equals)       자동 차단(add()시 hashCode()-->equals())
        사용하는 메서드       equals()만 사용                           hashCode() + equals() 둘 다 사용 
        순서 보장            입력 순서 유지                             순서 보장 안 됨 
        인덱스 접근           get(i) 가능                              불가 
        성능                 데이터 많으면 느림                         항상빠름         


5. 실무에서 사용 빈도 
    1) ArrayList 
        - 가장 많이 사용
        - 예) DB에서 조회한 결과, API 응답 데이터 등
    2) HashMap
        - 두 번째로 많이 씀
        - 예) 캐시, 설정값 관리, JSON 파싱 등
    3) HashSet 
        - 중복 제거할 때
        - 예) 이메일 목록, 태그 관리 등
    4) LinkedList, TreeMap, TreeSet 등은 특수한 상황에서만 사용함
