3. RESTful URL 설계 원칙 
     1) REST에서 URL은 리소스(명사)를 나타내고, 행위는 HTTP 메서드로 구분함 
          - 변경 전 (비추천)
               GET  /                   --> 목록 (리소스명이 URL에 드러나지 않음)
               GET  /detail/{id}        --> 상세 ("detail"은 동사성 표현 --> REST 안티패턴)
          - 변경 후 (권장)
               GET /books               --> 목록 (리소스명을 URL에 명시)
               GET /books/{id}          --> 상세 (리소스 계층 구조로 표현)               
     
     2)  /books 기준으로 통일하면 나중에 CRUD 확장이 자연스러움 
          GET     /books               --> 목록  
          GET     /books/{id}          --> 상세 
          POST    /books               --> 등록  
          PUT     /books/{id}          --> 수정  
          DELETE  /books/{id}          --> 삭제 

4. 리뷰 삭제 시 동작 순서 
     1) 사용자가 "삭제" 클릭
     2) form이 제출되기 직전에 confirm() 팝업이 뜸 
     3) A. "확인" 
          - confirm()이 true 반환 --> form 제출됨 (서버로 DELETE 요청)
        B. "취소"
          - confirm()이 false 반환 --> form 제출 중단 (아무 일도 안 일어남) 

5. 리뷰 삭제 후 알림(alert) 처리 
     1) 사용자가 "삭제" 클릭 --> confirm 팝업 --> "확인"
     2) form이 POST 전송 --> ReviewController.deleteReview() 실행
     3) Controller가 redirect:/books/{id}?deleted=true 로 응답 
     4) 브라우저가 새 페이지를 로딩 --> 이 스크립트가 실행됨
     5) URL에 ?deleted=true가 있으면 --> alert('리뷰가 삭제되었습니다') 표시
     6) alert 닫은 후 --> URL에서 ?deleted=true 제거 (새로고침해도 alert 안 뜨게)

7. "더 보기" 버튼 
     1) 3개 초과 리뷰를 펼치는 토클 버튼 
     2) th:if="${book.reviews.size() > 3}"
          -> 리뷰가 4개 이상일 때만 이 버튼을 HTML에 렌더링 
        th:text="${book.reviews.size() - 3}
          -> 숨겨진 리뷰 개수 계산 (예: 7개면 "4개")       

     3) JS onclick
          - querySelectorAll('.review-hidden')
               - 숨겨진 리뷰 요소들을 전부 찾음(4번째, 5번째,...)  
          - .forEach(el => el.classList.toggle('.review-hidden'))   
               - forEach: 찾은 요소들을 하나씩 반복
               - toggle(): 클래스가 있으면 제거, 없으면 추가 (스위치 ON/OFF)
                    - 지금은 review-hidden이 있는 상태이므로 -> 제거됨 
                    - CSS display:none 해제 -> 숨겨진 리뷰가 보임
          - this.style.display='none'
               - 버튼 자기 자신을 숨김                                         

8. 인라인 편집 패턴 (Inline Edit Pattern)
     1) 같은 위치에서 읽기 모드 <---> 편집 모드를 display 속성으로 
        전환하는 JavaScript UI 패턴

     2) 패턴 원리

          읽기 모드 (기본)                                            편집 모드 (수정 중) 
       -------------------------                                 -------------------------     
        읽기 영역         (display:block)                             읽기 영역         (display:none)
          : 사용자에게 보여주는 데이터 
            예-리뷰 본문, 별점, 날짜, 수정/삭제 버튼 

        편집 영역         (display:none)                              편집 영역         (display:block) 
          : 숨겨져 있음 -- 사용자에게 안 보임 

        사용자가 보는 화면 : 데이터만 보임 (읽기 전용)                    사용자가 보는 화면 :  수정 폼만 보임 (편집 가능)
