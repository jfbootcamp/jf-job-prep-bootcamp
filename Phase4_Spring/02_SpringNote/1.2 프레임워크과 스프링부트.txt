1. 프레임워크(Framework)란 무엇인가?
    1) 개발자가 필요로 하는 대부분의 기능을 미리 만들어 놓은 뼈대(골격)
        - 개발자는 뼈대 위에 비즈니스 로직만 채워 넣으면 됨
        - 비유) 바퀴를 다시 발명하지 마라 
    2) 비유 (집을 짓는다)
        - 프레임워크 없이 개발 (맨땅에서 집 짓기)
            - 벽돌 하나하나 직접 제작 
            - 수도/전기 배관 직접 설계
            - 안전 기준도 스스로 만들어야 함
            - 완성까지 시간이 매우 오래 걸림
            - 결과: 느리고, 버그 많고, 품질 불안정, 개발진행--> 시간 급증 
        - 프레임워크 사용 (아파트 골조 위에 인터리어)
            - 골조/배관/전기 이미 완성
            - 안전 기준 이미 적용됨
            - 인터리어(비즈니스 로직)만 집중!
            - 검증된 설계로 품질 보장 
            - 결과 : 빠르고, 안정적이고, 품질 균일, 개발진행 --> 시간 일정 

2. 프레임워크 vs 라이브러리
    1) 라이브러리
        - 내가 라이브러리를 호출한다 
            - 개발자가 제어권을 가짐 

    2) 프레임워크
        - 프레임워크가 내 코드를 호출한다
            - 프레임워크가 제어를 가짐 
            - 이것이 바로 IoC(제어의 역전)!
        - 규칙에 맞게 코드를 작성하면 
          프레임워크가 실행해줌   

3. Spring Framework  ---> Spring Boot 진화 
    1) Spring Framework
        - Java 기반에서 폭넓게 사용하는 오픈소스 프레임워크
        - 개발자가 필요로 하는 대부분의 기능을 지원 
            - 웹 애플리케이션 
            - 보안 (Security)
            - 클라우드 
    2) 하지만 문제가 있었음...
        - 설정이 너무 많음!
            - 개발자가 처리해야 하는 설정이 많아 짐 
        - 라이브러리(API) 의존성이 복잡함
            - 버전 충돌, 호환성 문제가 빈번 
        - 이해도 : 많은 시간과 노력 요구 
            - 학습 곡선이 매우 높았음 
    3) Spring Boot 2014 도입 
        - Rod Johnson
        - 복잡한 XML 설정 --> Auto Configuration
        - 복잡한 의존성 --> Starter 의존성 묶음 
        - 외부 WAS 배포 --> 내장 Tomcat으로 바로 실행
