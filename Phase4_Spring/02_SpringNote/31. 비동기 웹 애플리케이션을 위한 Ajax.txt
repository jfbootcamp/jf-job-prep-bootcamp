1. 비동기전송 (Asynchronous transmission)
    1) 작업이 완료될 때까지 기다리지 않고 다음 작업으로 넘어가기
       위해 데이터를 전송하거나 요청하는 프로세스를 말함.
    2) 이를 통해 데이터 전송이나 요청이 처리되는 동안 
       다른 작업을 계속할 수 있으므로 애플리케이션의 성능과 응답성 향상됨

    3) 일반적 서버에 요청을 하고 서버의 응답을 기다리는 동안 
       사용자 인터페이스(UI)를 차단하지 않는 작업이 포함됨.
       - 프로그램은 계속 실행됨
       - 결국 서버가 응답하면 콜백 함수나 Promise가 응답을 처리함.

3. JavaScript 비동기 전송 기술 
    1) XMLHttpRequest(XHR) 
        - 2000년대 초 Ajax의 시작점임 
        - 레거시 코드에 여전히 등장함                
        - 콜백 기반 비동기 처리 기술 

    2) 콜백이란?
        - 나중에 호출될 함수를 미리 등록해두는 패턴 
        - onreadystatechange에 함수를 등록하면 브라우저가 상태 변화 시
          자동으로 호출함.
        - 등록 순서 주의
            - 콜백 함수는 반드시 send() 호출 이전에 등록해야 함
            - 이후에 등록하면 초기 상태 변화(1~3)를 놓칠 수 있음     
    
    3) XHR 콜백 (vs fetch/axios)  
        - XHR은 콜백 함수로 이벤트를 처리함 
        - 주요 목록
            - 상태 관련
                - onreadystatechange  
                    - readyState가 변할 때마다 호출 (0+1+2+3+4)
                - onloadstart
                    - 요청이 시작될 때 (send() 직후)
                - onload 
                    - 요청이 완료됐을 때 (한 번만 호출)
                - onloadend 
                    - 성공/실패 상관없이 요청이 끝났을 때                                            
            - 오류 관련
                - onerror
                    - 네트워크 오류 (DNS 실패, 연결 거부 등)
                - ontimeout 
                    - xhr.timeout 시간 초과 시 
                - onabort
                    - xhr.abort()로 요청을 강제 취소했을 때    

    4) fetch + Promise(.then 체이닝) 구조  
        - Promise의 3가지 상태
            - 대기 (Pending) 
                - fetch() 호출 직후 응답을 기다리는 중 
            - 이행 (Fulfilled)
                - 응답 도착 
                - .then() 실행됨 (200이든 404든!) 
            - 거부,실패 (Rejected)
                - 네트워크 오류, DNS 실패 등 
                - .catch() 실행됨    
        
        - .then() 체이닝  
            - fetch(url) 호출 
                -> Promise<Response> 반환
                -> JS는 여기서 멈추지 않고 계속 실행

            - 첫번째 .then(response => ....)                                                                                    
                -> response.ok 확인 -> json() 호출 -> Promise<Data> 반환

            - 두번째 .then(data => ....)
                -> 실제 데이터 사용, 화면 랜더링 

            - .catch(error => ....)
                -> 오류 처리, 체인 어디서든 throw하면 여기로 점프

    6) axios                

4. XHR vs FETCH 비교 

    항목                            XHR                                             FETCH
   -----------------------------------------------------------------------------------------------------
    비동기 처리 방식       onreadystatechange 콜백등록                  .then().then().catch()  Promise 체이닝
    JSON 파싱            JSON.parse(xhr.responseText) 직접 파싱        response.json() 호출 (Promise 반환) 
    404/500 처리         xhr.status !== 200  직접 확인                 response.ok 확인 후 throw  필요 
    네트워크 오류         별도 onerror 이벤트 등록 필요                   .catch() 하나로 처리
    가독성               중첩 콜백  -- 들여쓰기 깊어짐                    체이닝 -- 흐름이 위->아래로 읽힘   

5. fetch + async / await  
    1) Promise를 동기 스타일로 표현함 
        - Promise의 문법적 설탕(syntactic sugar)임
            - 내부적으로 .then() 체이닝과 완전히 동일하게 동작함 
            - 더 읽기 쉬운 문법을 제공함 
        - 비동기 코드를 동기처럼 읽히게 해줌 
        - 현재 가장 널리 쓰이는 표준 패턴임
    2) async 함수
        - async function f()으로 선언하면 해당 함수는 항상 Promise를 반환함 
       await 키워드 
        - Promise가 완료될 때까지 해당 줄에서 실행을 일시 중단함 
        - async 함수 안에서만 사용 가능함      
       try / catch
        - .catch() 대신 try / catch로 에러를 처리함 
    3) 03-async.js
        - 순차 실행 vs 병렬 실행 타임라인 비교 
            - 순차 실행
                - 요청1 ------------
                - 요청2             -----------
                - 총 소요 = 요청1 + 요청2 = 901ms
            - 병렬 실행                               
                - 요청1 ------------
                - 요청2 ---------
                - 총 소요 = max(요청1,요청2) = 

6. axios 가이드 
    1) 자동 JSON 변환 
        - 응답 body를 자동으로 파싱함 
            - response.json() 호출이 불필요함 
            - 파싱된 데이터가 response.data에 바로 담김 
    2) 4xx/5xx 자동 throw 
        - HTTP 에러 상태를 자동으로 감지해 catch로 보냄 
        - fetch처럼 if(!res.ok)를 직접 확인할 필요가 없음 
    3) 인터셉터 
        - 모든 요청/응답에 공통 로직을 삽입함 
        - 인증 토큰 자동 주입, 에러 공통 처리 등에 활용함                     

7. Ajax 기술 발전 흐름 비교 (정리)
    1) XHR (XMLHttpRequest)
        - 가장 오랜된 방식, 콜백 기반 
        - 순서
            - xhr.open('GET', url, true);
            - xhr.onload = function() { JSON.parse(xhr.responseText) }
            - xhr.send()
                - 콜백 중첩 심화 시 "콜백 지옥" 발생
                - 에러 처리 (onerror, ontimeout, onabort)를 각각 별도로 등록 

    2) fetch 
        - 브라우저 내장 Promise 기반 API 
        - fetch(url)
            .then(res => res.json())
            .then(data => console.log(data))
            .catch(e => console.log(e));
        - Promise 체이닝으로 콜백 지옥 해결 
        - 단점 : 4xx/5xx가 와도 reject 안 됨 --> response.ok 직접 확인 필요
                JSON 파싱(.json())을 매번 직접 호출해야 함 
                Content-Type 헤더와 JSON.stringify()를 매번 직접 작성해야 함 

    3) async / await
        - fetch를 동기 코드처럼 읽히게 만드는 문법 설탕 
        - const res = await fetch(url);
          const data = await res.json();   // 파싱 여전히 직접 필요
        - 가독성 향상, 하지만 fetch의 단점은 그대로 유지 

    4) axios
        - fetch를 감싼 서드파티 라이브러리 
        - .json() 파싱 불필요 - 응답 body가 .data에 자동으로 파싱됨
        - Content-Type, JSON.stringify() 불필요 -- POST/PUT 시 자동 처리 
        - 4xx/5xx 자동 reject -> catch 블록에서 일괄 처리 
        - error.response.status로 상태 코드 접근 가능
