1. 빌드 도구가 필요한 이유
    1) 빌드 도구 없이 개발한다면?                               Gradle을 사용하면?
        - 라이브러리를 웹에서 수동으로 다운로드                     - build.gradle에 한 줄 추가로 자동 다운로드 
        - JAR 파일을 프로젝트 classpath에 직접 추가               - 의존성을 자동으로 관리하고 classpath 설정   
        - javac: 명령어로 직접 컴파일                            - gradle build 한 번으로 컴파일 + 테스트 + 패키징 
        - 배포 파일(WAR/JAR)을 수동으로 패키징                    - JAR/WAR 파일 자동 생성 
        - 라이브러리 버전 충돌을 직접 해결                         - Spring Boot Starter가 호환 버전 자동 결정 

    2) 빌드 도구 
        = 라이브러리 관리 + 컴파일 + 테스트 + 패키징을 자동화하는 도구  
            - 자바 진영
                - Maven(XML 기반)  vs Gradle(Groovy/Kotlin 기반)             

2. Maven 프로젝트 디렉토리 구조 
    1) HelloBoot/ (프로젝트 루트)
        - pom.xml 
            - 핵심!
            - 프로젝트 설정 파일 
                - 의존성, 빌드, 플러그인 관리 
        - src/
            - main/
                - java/
                    - com.example.demo/
                        - Application.java 
                            - 메인 클래스, @SpringBootApplication
                        - controller/
                            - 웹 요청 처리 - @Controller 
                        - service/
                            - 비즈니스 로직 - @Service 
                        - repository/
                            - DB 접근 - @Repository 
                        - config/
                            - 설정 클래스 (@Configuration)                            
                - resouces/
                    - application.yaml (서버/DB 등 설정)
                        - 자동 로딩
                    - templates/
                        - Thymeleaf 자동 인식, 별도 ViewResolver 설정 불필요!
                        - Thymeleaf HTML 파일 
                    - static/
                        - 정적 파일 자동 인식 
                        - CSS, JS, 이미지

            - test/   

    2) Maven 표준 디렉토리 구조를 따르면
       별도 설정 없이 자동으로 컴파일/빌드가 됨.
       - 설정보다 관례를 따름 
         (Convention over Configuration)                                         

3. pom.xml 구조 
    1) 프로젝트 좌표 (GAV)
        - groupId : 회사/조직 도메인 역순 
        - artifactId : 프로젝트 이름 
        - version      

        - 이 3개 조합이 프로젝트의 고유 ID   
    2) parent (부모 POM)
        - spring-boot-starter-parent v4.0.3
            - 의존성 버전 자동 관리
            - 플러그인 기본 설정 제공
            - Java 버전 등 공통 설정 상속   
    3) properties (속성)
        - 21
            - 프로젝트 전체에서 사용할 변수 선언한 곳 
    4) dependencies (의존성)
        - 프로젝트에서 사용할 외부 라이브러리 목록 
            - spring-boot-starter-webmvc
            - spring-boot-starter-data-jpa
            - spring-boot-starter-thymeleaf
            - mysql-connector-j
            - lombok 
    5) build / plugins
        - maven-compiler-plugin
            - lombok 어노테이션 처리기 설정     
        - spring-boot-maven-plugin 
            - 실행 가능한 JAR 생성 
    6) SNAPSHOT 
        - 개발 중 (수시로 변경)
       RELEASE 
        - 배포 완료 (고정)

       0.0.1-SNAPSHOT --> 아직 개발 중!
       1.0.0 --> 첫 정식 배포! 

4. 의존성(Dependency)과 Scope       
    1) 어떤 라이브러리를, 언제(Scope), 어떻게 사용하는지 정리

        Scope       컴파일   테스트   런타임   패키징      
        ------------------------------------------------------------------------
        compile      O       O       O        O     모든 단계에서 사용 
        runtime      X       O       O        O     실행 시에만 필요 (컴파일 불필요)
        test         X       O       X        X     테스트 코드에서만 사용 
        provided     O       O       X        X     서버가 제공 (JAR에 미포함) 

    2)  compile scope (기본)
        - spring-boot-starter-webmvc
            - 웹 MVC 개발 (Controller, REST API)
        - spring-boot-starter-data-jpa
            - DB 접근 (JPA/Hibernate)    
        - spring-boot-starter-thymeleaf
            - 서버사이드 HTML 템플릿 엔진 
        - lombok 
            - 반복 코드 자동 생성 

        runtime scope 
        - mysql-connector-j
            - MySQL JDBC 드라이버 (실행 시 필요)
        - spring-boot-devtools
            - 개발 시 자동 재시작, 라이브 리로드 

        test scope 
        - spring-boot-starter-*-test                                                                        
            - JUnit, Spring Test 등
