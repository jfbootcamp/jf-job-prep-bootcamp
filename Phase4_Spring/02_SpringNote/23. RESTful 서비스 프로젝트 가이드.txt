1. RESTful 서비스 
    1) REST 
        - Representational State Transfer
        - 자원을 URL로 표현, HTTP Method로 행위 구분 

    2) 기존
        - 중앙 집중식 (모놀리식)
        - Back-End : 모든 Service가 하나의 서버 
          Front-End : Thymeleaf, JSP (서버 종속)
        - 문제점
            - 하나 수정 --> 전체 재배포 
            - 프런트/백 강결합 
            - 프런트 개발자가 벡앤드 코드 필요 
            - 팀프로젝트 시 역할 분리 어려움       
    3) REST API 
        - 독립형 서비스 (마이크로 서비스, MSA)
        - Front-End: React, Vue.js (독립)
        - 통신 : GET/POST/PUT/DELETE + JSON
        - 장점
            - 프런트/백 독립 개발 & 배포 
            - JSON 표준으로 어디서든 소비 가능 
            - 팀프로젝트: 역할 분리 명확            

2. REST API 
    1) 요청 방식 + URL
    2) 고유한 주소(자원의 엔드포인트)로 자원에 접근하는 표준 방식 
    3)      HTTP Method        Endpoint URL         설명          Spring 어노테이션  
           -----------------------------------------------------------------------
             GET                /api/books        전체목록조회       @GetMapping
             GET                /api/books/{id}   특정데이터조회     @GetMapping    
             POST               /api/books        데이터 등록       @PostMapping 
             PUT                /api/books/{id}   데이터 수정       @PutMapping
             DELETE             /api/books/{id}   데이터 삭제       @DeleteMapping
    4) URL은 자원(명사) 중심, 행위는 HTTP Method로 표현
        -  /api/books     (O)
        -  /api/getBooks  (X) 

3. 왜 @Controller에서 @RestController로?
    1) 과거 
        - 서버가 HTML을 만들던 시절
        - @Controller + Thymeleaf
        - 서버가 HTML을 직접 만들어서 반환 
            - 브라우저는 받은 HTML을 그냥 표시 
        - 이슈
            - 모바일 앱에서 HTML을 못 씀 
            - React 같은 프런트와 연동 불가 
            - 화면 + 서버 동시 작업 불가 
    2) 전환점
        - "데이터만 주세요!"
            - "HTML 말고 데이터(JSON)만 주면 화면은 우리가 직접 만들게요"
        - React, Vue.js, 모바일 앱의 등장 
        - 프런트엔드 개발자
            - 순수한 데이터(JSON)만 필요
            - HTML 껍데기는 필요 없음
            - API 문서만 있으면 됨 
    3) 현재             
        - @RestController
            - JSON 데이터만 반환
                - 브라우저, 앱, 다른 서버 누구든 소비 가능 
                - 프런트/백 완전 분리 
            - Swagger로 API 문서 자동      
    4) @RestController를 사용하면 백엔드 팀은 API만 만들고,
       프런트 팀은 React로 화면만 만들면 됨.
       - JSON이라는 공통 언어로 소통 
       - Swagger가 API 계약서 역할            

4. @RestController
    1) @Controller + @ResponseBody 
        - @Controller
            - MVC에서 View 반환
            - 리턴값 --> ViewResolver --> HTML 랜더링
            - 서버가 HTML을 생성해서 반환
    2) JSON 직접 반환하는 컨트롤러 
        - 리턴값 --> Jackson --> JSON 직렬화 
        - View 없이 데이터(JSON)만 반환
        - Swagger UI가 자동 스캔하는 대상 

5. Step1 : 문자열 반환
    1) Spring은 응답을 보낼때 반환 타입 맞는 MessageConverter를 
       순서대로 탐색함 
       - 반환 타입: String 

       - 1순위 : StringHttpMessageConverter --> String 처리 가능 --> 바로 사용
       - 2순위 : MappingJackson2HttpMessageConverter (Jackson) --> 순서가 안 옴
    2) StringHttpMessageConverter가 Jackson보다 먼저 등록되어 있고,
       String 타입을 처리할 수 있으니 여기서 바로 처리가 끝나버림.  

6. JSON (JavaScript Object Notation)
    1) 데이터의 공통 언어 
    2) 사람이 읽기 쉽고, 기계도 파싱하기 쉬운 데이터 형식 
    3)      Java 객체 (서버 메모리)                                         JSON (네트워크 전송용)                            
          -------------------------                                      ---------------------
            Book book = new Book();             Jackson 라이브러리          
            book.id = 1L;                    -------------------   
            book.subject = "스프링과 AI";            직렬화
            book.price = 29000;              -------------------
            book.author = "이순신";           Java 객체 --> JSON
            book.page = 500;
                                                                        {
                                                                            "id": 1,
                                                                            "subject": "스프링과 AI",
                                                                            "price": 29000,
                                                                            "author": "이순신",
                                                                            "page": 500
                                                                        }
    4) 쉬운 비유
        - Java 객체 = 한국어 문서
        - Jackson = 번역기 (자동으로 변환)
        - JSON = 전 세계 공통어 (영어)

7. Jackson
    1) Spring Boot에 기본 내장된 JSON 변환 라이브러리
    2) 개발자가 직접 JSON 문자열을 만들 필요 없이,
       return bookViewDTO; 만 하면 자동으로  JSON 변환해줌

8. 초기 데이터 설정 
    1)         data.sql                   vs        CommandLineRunner
    ----------------------------------------------------------------------------------
    실행방식    sql 파일을 직접 실행                   Java 코드로 실행
    실행시점    Spring Boot 시작 시 자동              Spring Boot 시작시 run() 호출
    DB 종속성   있음 (MySQL문법)                      없음 (JPA Repository 사용)
    조건 분기   SQL로만 가능(제한적)                   Java 코드라 자유로움 
    외부API연동  불가                                 가능  

    2) 실무에서 사용 기준
        - 고정된 참조 데이터 --> data.sql 방식
            - 코드, 카테고리, 권한 등 변하지 않는 데이터
        - 로직이 필요한 초기화 --> CommandLineRunner 방식 
            - 조건, 분기, 외부 API 호출, 암호화 등이 필요할 때         

9. Swagger UI 테스트 순서 
    1) POST로 등록
    2) GET으로 확인
    3) PUT으로 수정 
    4) DELETE로 삭제 

    5) Java 어노테이션                          Swagger UI 결과
      --------------------------------------------------------- 
        - @Tag(name, description)             API 그룹 헤더   
        - @Operation(summary)                 접힌 상태 라벨 
        - @Schema(desc, example)              필드 설명 & 예시값 
        - @ApiResource(code, desc)            응답 코드 설명 
        - @GetMapping -> 파란 GET              HTTP 메서드 배지
        - @PostMapping  -> 초록 POST           Request body 입력 폼
