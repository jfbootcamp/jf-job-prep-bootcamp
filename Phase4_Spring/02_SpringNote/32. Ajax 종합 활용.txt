1. CRUD + REST API (Axios 버전)

    1) CRUD URI 설계
        - C -> POST     /api/items          -> 201 Created
          R -> GET      /api/items          -> 200 OK 
          U -> PUT      /api/items/{id}     -> 200 OK
          D -> DELETE   /api/items/{id}     -> 204 No Content

    2) 비동기 CRUD
        - 모든 CRUD 작업은 Axios 비동기 요청으로 처리됨 
        - 전통 방식(<form> submit)은 요청마다 페이지 전체가 새로고침되지만,
          이 프로그램은 Axios가 백그라운에서 서버와 통신하고
          응답을 받으면 필요한 DOM(테이블, 폼, 결과 박스)만 부분적으로 업데이트함
          -> 이것이 Ajax(Asynchronous JavaScript and XML)의 본질임  

        - submitForm() - POST  /api/items       -> 페이지 새로고침 없이 등록 후 목록 갱신
                       - PUT   /api/items/{id}  -> 페이지 새로고침 없이 수정 후 목록 갱신  
          loadItems()  - GET   /api/items       -> 페이지 새로고침 없이 목록만 갱신
          deleteItem() - DELETE /api/items/{id} -> 페이지 새로고침 없이 삭제후 목록 갱신

    3) Thymeleaf vs React/Vue - Ajax 사용 방식 차이 
        - Thymeleaf 프로젝트 
            - 페이지 이동, 폼 제출 -> <form> 기반 동기 방식이 기본 
            - 부분 업데이트가 필요한 경우에만 Ajax 병행 사용 
            - 예) username 중복 확인, 자동완성, 좋아요 토클, 무한 스크롤 

        - React / Vue (SPA)
            - 페이지 전환 포함 모든 서버 통신을 Ajax(Axios 등)로만 처리 
            - 서버는 HTML을 내려주지 않고 JSON API만 제공 (백엔드 = REST API)
            - Axios CRUD 패턴이 그대로 적용됨 

        - 즉, Thymeleaf = 동기 + Ajax 병행 / React.Vue = Ajax 전용 

2. 프런트엔드 Ajax 패턴 
    1) REST API 설계 규칙 (HTTP 메서드 + 상태 코드)
    2) Axios + async / await 조합 - 현업에서 가장 많이 쓰는 패턴 
    3) 등록/수정 폼을 하나로 합치고 editMode 플래그로 분기하는 형식 
        - Thymeleaf(서버 랜더링)에서는 유지보수를 위해 파일을 분리하는 것이 맞음
            - register.html / edit.html 별도 운영 
        - React / Vued에서는 페이지 이동이 없으므로 하나의 폼에서 
          editMode 플래그로 동작만 바꾸는 통합 방식이 자연스럽고 실무 표준임.

        - 즉, Thymeleaf = 폼 파일 분리 / Ajax-SPA = 하나의 폼 + 플래그 분기 

3. Ajax 종합 활용
    1) 인메모리 List 사용 
    2) 인증/인가 없음
    3) 에러 처리 단순
    4) alert() 사용 
    5) CRUD 전체 흐름 
        - 조회(loadItems)
            - loadItems()   -----------> GET /api/items    -----------> 서버  ---------> 200 OK    ------> renderTable()
            페이지로드/버튼 클릭        keyword 있으면 ?keyword=값         DB 조회           Item[] 배열          행 동적 삽입 

        - 등록 / 수정 (submitForm)
            - submitForm()  --> currentEditId 확인 --> POST /api/items  --> 201 Cread 
                                     false/true         신규등록               생성된 Item 
                                                  --> PUT /api/items/{id} --> 200 OK  --> resetForm() + loadItems() 
                                                        수정                  수정된 Item      폼 초기화 + 목록 새로고침 
        - 삭제 (deleteItem)
            - 삭제 버튼 --------->  confirm()   --------->  DELETE /api/items/{id}   -----> 204 Not Content ---> loadItems()
                deleteItem(id)      사용자 확인                body 없음 - URL에 id만            body 없음          목록 새로고침
